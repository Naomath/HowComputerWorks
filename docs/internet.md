## 基礎知識
### はじめに
Wikipediaを引用すると、「インターネット（英: the Internet）は、 TCP/IPプロトコルを用いて接続された世界規模のコンピュータネットワークである。」と出てきます。
ここで用語を整理すると、TCP/IPプロトコルとは接続の規格のことで、コンピュータネットワークとは複数のコンピューターが接続されたシステムを言います。
家庭のルーターを起点としてネットーワークや、会社や病院内のネットワークもコンピューターネットワークであり、それらがインターネットと繋がっています。

「インターネットに接続する」、といえばChromeなどのブラウザを思い浮かべますが、全世界をまたがるコンピューターネットワークに参画する、というイメージで、それらのネットワークに参加する何百億台のコンピューターと相互通信できるようになる、と考えたほうがいいと思います。

インターネットを勉強するときのポイントとして、以下の2点を気に留めながら考えると良いかと思います。

- より馴染みのあるネットワークシステム（郵便など）とのアナロジーを考える
- 日頃のインターネットの仕組み(Youtubeやメールなど)を思い浮かべ、それらを実現するためには何が必要かを考える

### パケット交換
インターネットでの通信はパケット交換で行われます。
パケット交換では、送信するデータをパケットに分割し、そのパケットに宛先のアドレスを紐付けて、送信します。
対比するものとしては、回線交換があり、これは電話で使われる方式で、通信端末同士で回線を独占して、情報を送り合います。
パケット交換は、回線を独占せずに、同一回線にいくつもの異なる宛先のパケットが流れることになります。

災害時に、「普通の電話よりもLINE電話のほうが繋がりやすい」と言われることがありますが、これは前者が回線交換、後者がパケット交換であるからです。
回線交換では、限られた回線の数しかないため、それらが全て使用されているとつながることができませんが、一方でパケット交換では回線を共有するため、通話の品質（遅延など）はともかくとして、一般的にはつながりやすいです。
インターネットも、通信という電話や無線やらの文脈の延長線上にあるため、このような回線交換と比べられることがあるわけです。

### インターネットでの識別子
インターネットでの識別子といえば、IPアドレスが有名かと思います。
IPアドレスは規格としてIPv4とIPv6があるのですが、現在のインターネットで使われているのはIPv4のほうなので、そちらの解説をします。
IPv4ではアドレスは32bitで表されます。
$2^{32}=4294967296$で約43億個のアドレスがありますが、これでは足りないのでは、と思われるでしょう。
実際に足りないため、IPv6は128bitで構成され、約340澗個のアドレスがあります。
ただし、現在はIPv4が基本で、プライベートIPアドレスがその不足分を補っているからです。

まずは、自身のコンピューターのIPアドレスを以下のコマンドで調べてみましょう。
```bash 
ip -4 addr
```
これで自身のLinuxのIPv4のネットワークで割り振られている番号がわかります。
``127.0.0.1``というのは自分自身を指定する特別のIPアドレスになります。

それでは次に``google.com``のWebアドレスを調べてみましょう。
```bash
nslookup google.com
```

グローバルIPアドレスは限られており、一意に定める必要があるので、適切に割り当てる必要があります。
全世界で管理している団体がIANAであり、アジアの管轄をIANAから依頼されているのがAPNICで、JPNICが日本での管轄をAPNICから依頼されているという形式になっています。
JPNICはアドレスを割り当てるわけですが、アドレス一つ一つを割り当てるというよりは、どこからどこまでのアドレス範囲、アドレス空間を割り当てます。
[このサイト](https://ipv4.fetus.jp/jp?_lang=ja-JP)から日本に割り当てられているアドレス空間を確認できます。
余談ですが、パケットにはどのIPアドレスから来たかの送信元アドレスがついているので、送信元アドレスと上記のようなサイトを照らし合わせれば、どこからその通信がやってきたのか（例えば、サイバー攻撃もパケットなのでどこからきたかを分析するのは大事）がわかります。

例えば、``1.0.16.0/20``がJPNICには割り振られていますが、この意味はIPアドレスが``1.0.16.0``~``1.0.31.255``の範囲で使えるということです。
``1.0.16.0/20``を32bitで表すと、``00000001 00000000 00010000 00000000``になりますが、これの上位20bit分は指定で、残りの``32-20=12``bit分は自由に使えるよ、ということです。
ですので、自由に変えられるビットを``X``で表すと、``00000001 00000000 0001XXXX XXXXXXXX``です。
JPNICはさらにこのアドレス空間をたとえば、``1.0.20.0/23``=``00000001 00000000 0001010X XXXXXXXX``というように分けて配ります。

また、以下の三つのアドレス空間はプライベートアドレス空間として、グローバルIP番号としては割り振られません。
内部的なコンピューターネットワークを構築する際には、これらの空間を用いることで十分です。
日常生活で用いるような機器にはこれらのプライベートIPアドレスが割り振られていることが多いですが、例外として、スマホをWiFiではなくモバイル通信で接続しているときは、契約しているキャリアが保持しているグローバルIPが割り振られます。

| アドレス空間 | 用途 | 
|:-----------|:------------|
| ``10.0.0.0/8`` | 企業や大学などの大規模ネットワーク |
| ``172.16.0.0/16``   | 中規模。VPNネットワークで使われることが多い |
| ``192.168.0.0/24``   | 小規模。家庭用WiFiのデフォルト |

一つの疑問として、プライベートIPアドレスを持つPCからウェイブサイトにアクセスするときに、そのサイトのWebサーバーはグローバルIPアドレスを持っているだろうから、PC→Webサーバーへとパケットは送ることができても、その逆はできないのでは？、というものがあるかもしれません。
これは後述するNATという技術を使うことで解決できます。

さて、このIPアドレスには**階層性**という重要な性質があります。
``10.0.0.0/8``を東京大学ネットワークのアドレス空間として、駒場キャンパス一号館102号室のWiFiに接続される機器へのアドレスの割り振りを考えます。

### ポート番号
ポート番号とは、ネットワーク通信で、同じIPアドレス内でどのアプリケーションやサービスと通信するのかを識別する番号で、0から65535までの範囲に存在します。
通信する際は、宛先と送信元のIPアドレスのみならず、ポート番号も使うことで、一つのコンピューターで複数の通信を確立することができます。

前半の方の番号は、どの通信に使うかが決まっています。
例えば、80番はhttpサーバーの番号として予約されています。
ですので、例えば、アドレス``192.0.2.1``のhttpサーバーにパケットを送信するときは、``192.0.2.1:80``というようにポート番号まで指定します。

##　　TCP/IPプロトコル
現在のインターネットで利用されるプロトコルスイートはTCP/IPプロトコルです。
TCP/IPプロトコルでは以下の四つのレイヤーに分かれます。

| 層名 | 役割 | Protocol Data Unit (PDU) |  代表的なプロトコル（TCP/IP）|
| ------------------------- | ----------------------------------------------------------------- | ------------------------------ | ------------------------------------------ |
| **アプリケーション層** | ユーザーやアプリケーションに直接サービスを提供する層。通信内容の形式や手順を定義し、データの意味を扱う。 | なし | HTTP（Web通信）、SMTP（メール送信）、POP3/IMAP（メール受信）、FTP（ファイル転送）、DNS（名前解決）、SSH（リモート接続） |
| **トランスポート層**              | アプリケーション間の通信を管理する層。データの分割・再構成、エラー検出、信頼性の確保、ポート番号による識別などを行う。       | セグメント(TCP)、データグラム(UDP) | TCP（信頼性のあるコネクション型通信）、UDP（高速なコネクションレス通信）                                    |
| **インターネット層**              | ネットワーク全体でのデータ転送経路を決定する層。パケットのアドレス指定やルーティングを担当する。| パケット | IP（IPv4/IPv6：パケットの配送）、ICMP（エラー通知や診断）、ARP（IPアドレスからMACアドレスの解決）               |
| **リンク層（ネットワークインターフェース層）** | 物理的な通信媒体とのインターフェースを担当し、同一ネットワーク内でのデータ転送を行う層。フレーム化やMACアドレス管理なども行う。 | フレーム | Ethernet（有線LAN）、Wi-Fi（IEEE 802.11）、PPP（ポイント・ツー・ポイント通信）、MAC |


下の図において、「元のデータ」とは、アプリケーション層の、例えばWebページのHTMLをください、とかそれへの返答のHTMLそのものですが、それにどんどん各レイヤーでヘッダが付け加えられたり、分割されていき、最終的にはL2ヘッダとL2トレーラをつけた状態で、LANケーブルやWiFiから信号として出発します。

PDUとはそれぞれの層での、ヘッダとペイロード(通信データの中身)のひとまとまりの呼び名です。
一般的に、パケット交換方式であることからも、パケットがインターネットでのデータ通信の単位だと思われがちですが、電気的な信号として直接変換されるものはフレームです。

###　 アプリケーション層
アプリケーション層としては、HTTPやSMTP、TLS/SSLなどがあります。
``http://example.com``などの``http://``はURLのスキームとspaceばれる部分で、利用するプロトコルを表します。
これらは通信のフレームワークであり、httpリクエストなどをふんだんに使うことでWebブラウザが動いています。
ちなみに、ここからはhttpで説明をしますが、通常のネットワークの通信は暗号化がされているhttps通信で動いています。
たまに、ウェブサイトにアクセスすると、「保護されていない通信」などの警告がありますが、httpsを用いずにhttpで通信しているサイトです。

### トランスポート層
トランスポート層では通信を管理し、相手にデータが要求を満たして届くことを保証します。
TCP/IPプロトコルスタックでは、TCPとUDPという二つのプロトコルが用いられます。
違いをまとめると以下のようになります。

| 項目      | TCP (Transmission Control Protocol)               | UDP (User Datagram Protocol)   |
| ------- | ------------------------------------------------- | ------------------------------ |
| 通信方式    | コネクション型（接続を確立してから通信）                              | コネクションレス型（接続なしで送信）             |
| 信頼性     | 高い（パケットの再送・順序制御・エラーチェックあり）                        | 低い（再送・順序制御なし）                  |
| データの順序  | 保証される（送信順と受信順が同じ）                                 | 保証されない（順序が入れ替わる可能性あり）          |
| エラーチェック | あり（エラー検出・再送で信頼性確保）                                | あり（検出のみ。再送は行わない）               |
| 通信速度    | 遅い（信頼性確保のためのオーバーヘッドが大きい）                          | 速い（最低限の処理で即送信）                 |
| 通信の開始   | 3way-handshakeが必要                                    | 不要（即送信可能）                      |
| 利用例     | Web（HTTP/HTTPS）、メール（SMTP/POP3/IMAP）、ファイル転送（FTP）など | DNS、動画ストリーミング、オンラインゲーム、VoIP など |

TCPではコネクションの確立のために、初めに3way-handshakeが行われます。
この様子を[Wireshark](https://www.wireshark.org/)を用いて見てましょう。
Wiresharkとは、インストールしているPCに流れてくるパケットを解析するソフトウェアです。
正確には、パケットではなくて、フレームごとに表示しますが、よく「パケットキャプチャ」と言います。

Wiresharkのフィルタリングのバーに``tcp.port == 80``と入力して、TCPでポート80番との通信だけを表示します。
キャプチャを開始している状態で、以下のコマンドを実行してください。
```bash
curl -v --http1.1 http://example.com
```

このときの実行結果が以下です。
<figure>
  <img src="/HowComputerWorks/images/wireshark.png" width="1200">
  <figcaption>Wiresharkでのキャプチャ結果</figcaption>
</figure>

最初の三つのキャプチャを見ると、手元のPCのアドレスが``10.100.115.27``で、``example.com``のアドレスが``23.192.228.80``とわかります。
3way-handshakeは以下のように行われています。

1. 手元のPC``10.100.115.27``から``[SYN]``パケットを送り、**接続要求の依頼**をする
2. ``example.com``のHTTPサーバー``23.192.228.80``が``[SYN,ACK]``パケットをおくり、**接続要求への応答と同意**をする
3. 手元のPC``10.100.115.27``から``[ACK]``パケットを送り、**接続への同意を確認したことへの通達**をする

このように3回に分けて、パケットを送り合いコネクションを確立しているため、**3*way*-handshakeと言います。

また、TCPは輻輳制御や再送などによりスムーズに通信が行われるような制御もしています。
詳しくはここには書きませんが、もし興味があれば調べて見てください。

一方で、UDPはコネクションを確立せず、パケットが確実に到着することも保証しません。
ただし、その分、やり取りの確認のための通信がないため、通信が早く、途中のデータがロスしても問題ないライブ動画配信などで用いられます。

### インターネット層
インターネット層ではネットワーク全体でのデータの転送経路を決定します。
IPアドレスが
インターネット層では、ネットワークのノードとしては、ホストとルーターの二つの役割があります。
ネットワークに接続する機器はどちらの機能も持っています。
WiFiに接続するときのルーターもこのルーターなのですが、L2スイッチ(リンク層で解説)としての役割も持っています。

| 名称              | 役割                       | 例                     |
| --------------- | ------------------------ | --------------------- |
| **ホスト（Host）**   | IPパケットの送信元または宛先として機能する端末 | PC、スマートフォン、サーバ など     |
| **ルータ（Router）** | IPパケットを別のネットワークへ転送する中継装置 | 家庭用ルータ、企業ネットワークルータ など |


ノードとは、ノードとエッジの集合で構成されるグラフのノードのことです。
グラフは以下の図のように示される構造のことで、例えば、``1``がノードで、``1``と``5``を繋ぐのがエッジです。

  <figcaption>グラフの例　出典:Wikipedia </figcaption>
</figure>

ここで意識をしたいのは、あるノードから直接アクセスできるのはエッジで繋がっているノードのみ、ということです。
インターネットもネットワーク構造でグラフで表されるため、ホストからはエッジでつながるノードへしか直接はアクセスできないはずですが、実際は、任意の二つのノードで通信ができます。
これを可能にしているのが、IPアドレスの階層性と経路表です。

ここでは以下の仮想大学ネットワークを例にとって考えます。
<figure>
  <img src="/HowComputerWorks/images/networkgraph.png" width="1200">
  <figcaption>仮想大学ネットワーク </figcaption>
</figure>

本郷ネットワークに属する``10.64.16.1``のサーバーから駒場1号館102教室のWiFiに接続されている``10.1.16.1``のスマートフォンまでどのように転送するでしょうか。
ここでルーターは経路表にそって、次にパケットを配送する先を決めます。

経路表はネットワークごとにどのルーターに送るかが決めてあります。
例えば、``10.0.0.1``のルーターの経路表は以下のようになります。

| ネットワーク | 次のルーター |
| ---------- | ---------- | 
| 10.2.0.0/16 | 10.2.0.1 |
| 10.64.0.0/10 | 10.64.0.1 |

本来はもっと接続先があるはずなので、これより大きいですが、例えばパケットが本郷ネットワークから駒場ネットワークに入ってきたもので、一号館のIPアドレスを指すものだったら、``10.2.0.1``に配送するわけです。

また、経路表には「デフォルトゲートウェイ」と呼ばれる項目があり、経路表に該当しないネットワーク宛てのパケットは、このデフォルトゲートウェイに送信されるようになっています。
経路表は全てのノードにあり、例えば、自宅のWiFiに接続される機器のデフォルトゲートウェイはそのWiFiということになっています。
